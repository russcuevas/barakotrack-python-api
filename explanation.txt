================================================================================
  BARAKO TRACK: CONVOLUTIONAL NEURAL NETWORK (CNN) SYSTEM EXPLANATION
================================================================================

1. WHAT MODEL IS USED?
--------------------------------------------------------------------------------
The system uses the **MobileNetV2** Deep Convolutional Neural Network (CNN) architecture, 
pre-trained on the ImageNet dataset (1.4+ million images across 1,000 object categories).

Key Specifications:
- Model Architecture: MobileNetV2 (Inverted Residuals & Linear Bottlenecks)
- Deep Learning Framework: PyTorch (`torch` & `torchvision`)
- Pre-trained Weights: ImageNet (`MobileNet_V2_Weights.DEFAULT`)
- Feature Representation: 1,280-Dimensional Deep Feature Vector
- Microservice Layer: Python Flask API running on port 5000 (`python_service/app.py`)

--------------------------------------------------------------------------------
2. HOW MOBILENETV2 CNN FEATURE EXTRACTION WORKS STEP-BY-STEP
--------------------------------------------------------------------------------

Step 1: Input Preprocessing & Tensor Normalization
  - Uploaded image (file bytes or URL) is loaded and converted to RGB color format.
  - Image is resized to standard input dimensions of 224 x 224 pixels.
  - Converted into a PyTorch FloatTensor of shape [1, 3, 224, 224].
  - Normalized using standard ImageNet mean and standard deviation:
      * Mean:   [0.485, 0.456, 0.406]
      * StdDev: [0.229, 0.224, 0.225]

Step 2: Deep Feature Extraction via Inverted Residual Layers
  - The normalized image tensor is passed through MobileNetV2's feature extractor 
    composed of Depthwise Separable Convolutions and Bottleneck Residual blocks.
  - The final classification layer (`classifier[1]`) is replaced with an `Identity()` 
    function to bypass label classification and extract raw deep feature embeddings.
  - Output: High-level 1,280-dimensional feature embedding vector representing object 
    shapes, contours, patterns, colors, and visual semantic attributes.

Step 3: L2 Vector Normalization
  - The 1,280-dim feature vector is normalized using Euclidean L2 norm:
      v_normalized = v / ||v||_2
  - Ensures the feature embedding vector lies on a unit hypersphere, making distance 
    and similarity computations robust against brightness and scale variations.

--------------------------------------------------------------------------------
3. IMAGE SIMILARITY MATCHING (COSINE SIMILARITY)
--------------------------------------------------------------------------------
To compare a Lost Item image embedding (v1) against a Found Item image embedding (v2):

  Cosine Similarity = (v1 . v2) / (||v1||_2 * ||v2||_2)

- Computes the cosine of the angle between the two 1,280-dimensional vectors in 
  high-dimensional embedding space.
- Produces a raw visual match confidence score between 0.0% and 100.0%.

--------------------------------------------------------------------------------
4. HYBRID MATCHING ARCHITECTURE & SYSTEM INTEGRATION (LARAVEL + PYTHON)
--------------------------------------------------------------------------------
Laravel communicates with the Flask Python microservice via HTTP requests 
(`CNNEngineService.php` & `MatcherController.php`):

1. Score Calibration (`calibrateImageScore`):
   - Calibrates raw CNN scores to account for real-world lighting and camera angle variances.
   - Raw scores >= 35.0% are scaled linearly into 58.0% - 98.5% confidence matches.

2. Hybrid Matching Formula:
   - Final Score = (Calibrated MobileNetV2 Visual Score * 60%) + (Semantic Text Score * 40%)
   - Semantic Text Score (40%): Title & description keyword overlap, category alignment (+35 pts), 
     and synonym dictionary matching (e.g., phone/mobile, bag/backpack, pen/marker).

3. Decision Threshold:
   - Matches with a score strictly > 45.0% are highlighted to students and admins 
     as potential lost-and-found matches.
